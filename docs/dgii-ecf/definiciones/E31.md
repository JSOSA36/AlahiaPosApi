# E31 — Factura de Crédito Fiscal Electrónica

**TipoeCF:** 31  
**Clase:** `Ecf31Definition`  
**XSD:** `e-CF 31 v.1.0.xsd`  
**Estado DoD:** Completo

## Propósito

Comprobante electrónico de crédito fiscal para operaciones con contribuyentes. Canal: e-CF individual (`recepcion` / testecf).

## Campos obligatorios

| Sección | Campo | Notas |
|---------|-------|-------|
| IdDoc | TipoeCF, eNCF | 31 / 13 caracteres |
| IdDoc | FechaVencimientoSecuencia | Precert: suele exigir `31-12-2028` |
| IdDoc | TipoIngresos, TipoPago | TipoIngresos 01–06 |
| Emisor | RNCEmisor, RazonSocialEmisor, DireccionEmisor, FechaEmision | |
| Comprador | RazonSocialComprador | Sin RNC → `000000000` |
| Totales | MontoTotal | |
| DetallesItems | ≥ 1 Item | Campos Item comunes |

## Campos opcionales

| Sección | Campo | Notas |
|---------|-------|-------|
| IdDoc | IndicadorMontoGravado, TablaFormasPago | Máx. 7 formas |
| Emisor | NombreComercial, Municipio, Provincia, teléfonos, correo, factura interna | Prov/Mun = código 6 dígitos |
| Comprador | Correo (antes de Direccion), Direccion | |
| Totales / Item | Montos ITBIS, descuentos línea, etc. | Solo si aplican |

## Campos prohibidos

| Sección | Campo | Motivo |
|---------|-------|--------|
| Root | InformacionReferencia | No aplica |
| Totales | MontoPropinaLegal | No existe en XSD Totales e-CF |

## Restricciones del XSD

- Sin namespace; RNC 9|11; fechas `dd-MM-yyyy`; `FechaHoraFirma` con hora.
- `FechaVencimientoSecuencia` y `TipoIngresos` con `minOccurs=1`.

## Reglas de negocio de la DGII

- Solo canal e-CF individual (no RFCE).
- Crédito fiscal: comprador identificado (RNC o placeholder según flujo).

## Restricciones y validaciones especiales

- `eNCF` longitud 13 (validación definición).
- Al menos un Item.
- Teléfono solo si formato `###-###-####`; correo solo si regex XSD-compatible.
- Motor omite nodos vacíos / prohibidos.

## Casos especiales

- Ambiente de prueba: **testecf**.
- No re-serializar XML firmado con `XmlWriter.Save` (rompe firma).
