# E32 — Factura de Consumo Electrónica

**TipoeCF:** 32  
**Clase:** `Ecf32Definition`  
**XSD:** `e-CF 32 v.1.0.xsd` (+ `RFCE 32 v.1.0.xsd`)  
**Estado DoD:** Completo

## Propósito

Factura de consumo (B2C). Según `MontoTotal` se envía por e-CF individual o por **RFCE**.

## Campos obligatorios

| Sección | Campo | Notas |
|---------|-------|-------|
| IdDoc | TipoeCF, eNCF, TipoIngresos, TipoPago | Sin FechaVencimiento en XSD |
| Emisor | RNCEmisor, RazonSocialEmisor, DireccionEmisor, FechaEmision | |
| Comprador | RazonSocialComprador | RNC **opcional** (no forzar 000000000) |
| Totales | MontoTotal | Define canal RFCE vs ECF |
| DetallesItems | ≥ 1 Item | |

## Campos opcionales

| Sección | Campo | Notas |
|---------|-------|-------|
| IdDoc | IndicadorMontoGravado, TablaFormasPago | |
| Comprador | RNCComprador, Correo, Direccion | |

## Campos prohibidos

| Sección | Campo | Motivo |
|---------|-------|--------|
| IdDoc | FechaVencimientoSecuencia | No existe en XSD E32 |
| Root | InformacionReferencia | No aplica |
| Totales | MontoPropinaLegal | Fuera de XSD Totales |

## Restricciones del XSD

- IdDoc sin `FechaVencimientoSecuencia`.
- `TipoIngresos` obligatorio.
- RFCE: XSD/resumen distinto; e-CF 32 firmado localmente aporta el código de seguridad.

## Reglas de negocio de la DGII

- `MontoTotal < 250_000` → RFCE (`recepcionfc`).
- `MontoTotal ≥ 250_000` → e-CF individual.
- Constante: `Ecf32Definition.UmbralRfceMontoTotal` (orquestador).
- **RNC comprador si MontoTotal ≥ 250_000:** obligatorio, 9 u 11 dígitos válidos (no vacío ni todo ceros). Validado en `Ecf32Definition.Validar` vía `EcfRncRules` (falla en ERP/API antes de DGII).

## Restricciones y validaciones especiales

- Definición marca `FechaVencimientoSecuencia` como **Prohibido** (no emitir aunque venga en DTO).
- Umbral RFCE documentado en definición; el **enrutamiento** es del orquestador, no del XML Builder.
- Pre-validación SSoT: `IFiscalDocumentoValidator` → `Ecf32Definition.Validar` (RNC ≥250k, IndicadorMontoGravado, etc.).

## Casos especiales

### RFCE (orquestador)

1. Firmar e-CF 32 local (no enviar ECF completo).
2. `CodigoSeguridadeCF` = primeros 6 de `SignatureValue` (sin espacios).
3. Armar y firmar RFCE; POST FC.
4. No re-guardar XML firmado con `XmlWriter.Save`.
